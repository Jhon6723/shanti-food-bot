# Deployment Guide

## Requirements

- Docker + Docker Compose
- Node.js 22 (only for local development without Docker)
- WhatsApp Provider: Meta Cloud API **or** OpenWA (self-hosted) — see `.env.example`

## Environment Variables

Copy `.env.example` to `.env` and fill it out. The active provider is controlled by `WHATSAPP_PROVIDER`:

```env
# PostgreSQL
POSTGRES_USER=shanti
POSTGRES_PASSWORD=shanti123
POSTGRES_DB=shanti_food
DATABASE_URL=postgres://shanti:shanti123@localhost:5433/shanti_food

# Provider: meta | openwa
WHATSAPP_PROVIDER=openwa
```

See the sections for each provider below for specific variables.

## Docker Compose (Recommended)

```bash
# Start everything (PostgreSQL + Bot)
docker-compose up -d

# View logs
docker-compose logs -f app

# Rebuild after changes
docker-compose up -d --build

# Stop
docker-compose down
# Stop and delete data
docker-compose down -v
```

## Local Development (without Docker)

```bash
# 1. You need PostgreSQL running locally
#    or point DATABASE_URL to a remote database

# 2. Install dependencies
npm install

# 3. Run in dev mode (tsx watch)
npm run dev

# 4. Or build and run
npm run build
npm start
```

## WhatsApp Providers

### Provider: Meta Cloud API

Required variables in `.env`:

```env
WHATSAPP_PROVIDER=meta
WHATSAPP_PHONE_NUMBER_ID=...
WHATSAPP_BUSINESS_ACCOUNT_ID=...
WHATSAPP_ACCESS_TOKEN=...
WHATSAPP_VERIFY_TOKEN=...    # verification token (you invent this)
WHATSAPP_APP_SECRET=...      # production: HMAC SHA-256
```

Register webhook in [Meta Developers](https://developers.facebook.com):
- **Callback URL**: `https://<your-domain>/api/v1/webhooks/whatsapp`
- **Verify Token**: the same value as `WHATSAPP_VERIFY_TOKEN`
- **Subscribe to**: `messages`

### Provider: OpenWA (self-hosted)

Required variables in `.env`:

```env
WHATSAPP_PROVIDER=openwa
WHATSAPP_PROVIDER_URL=http://localhost:2785
WHATSAPP_PROVIDER_API_KEY=owa_k1_...   # generated by OpenWA on startup
WHATSAPP_OPENWA_SESSION=<UUID>          # session UUID (not the name)
WHATSAPP_PROVIDER_WEBHOOK_SECRET=...   # production: HMAC SHA-256
```

See `docs/OPENWA.md` for the complete gateway setup guide.

## Expose to Internet (Webhook)

Both providers require a public HTTPS URL to receive webhooks.

### Option A: Cloudflare Tunnel (free, fast)

```bash
# Install cloudflared
sudo apt-get install -y cloudflared

# Create temporary tunnel (points to Shanti's port)
cloudflared tunnel --url http://localhost:3000

# It will give you a URL like:
# https://abc123.trycloudflare.com
```

Use `https://abc123.trycloudflare.com/api/v1/webhooks/whatsapp` as the webhook URL in the provider.

### Option B: Cloud hosting (production)

Recommended platforms:
- **Railway** — `railway.app`, PostgreSQL included, automatic deployment from GitHub
- **Render** — `render.com`, free tier available
- **Fly.io** — `fly.io`, very fast, good price

In all of these, configure `DATABASE_URL` with the PostgreSQL connection they provide.

## SSL in Production

The bot automatically detects when to use SSL:

```typescript
// connection.ts
const isLocalOrDocker = /localhost|127\.0\.0\.1|db|postgres/.test(DATABASE_URL);
ssl: NODE_ENV === 'production' && !isLocalOrDocker ? { rejectUnauthorized: false } : false;
```

If you use Railway/Render/Fly, `DATABASE_URL` will point to an external hostname and SSL will activate automatically.
